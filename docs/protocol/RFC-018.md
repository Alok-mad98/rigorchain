# RFC-018 — RES-Transfer ORU Fee Destroy (Circulation Sink)

| Field | Value |
|-------|-------|
| **Status** | Implemented in production `core/src/` |
| **Scope** | Destroy a fixed share of ORU network fees paid by RES-transfer transactions |
| **Relationship to RFC-020** | Complements RFC-020. RFC-020 prices RES *creation*; this RFC sinks ORU on RES *circulation*. Listed as out-of-scope in RFC-020 §8 |
| **Relationship to POOL-F** | Unchanged: fees remain ORU-only (`nFeesRes == 0`) |

---

## 1. Summary

RES spends already pay network fees on the ORU leg. Paying those fees in full to
coinbase makes ORU’s long-run sink depend only on Convergence / mint demand.

This RFC redirects a **fixed share** of ORU fees on **RES-transfer** transactions
away from coinbase. The unclaimed share never enters the UTXO set and is therefore
destroyed. The sink scales with RES adoption (transfer volume × fee market).

```
claimable_ORU = (Σ fees_ORU − destroy_RES_transfer) + block_subsidy
destroy_RES_transfer = Σ_{tx ∈ RES-transfer} floor(fee(tx) · NUM / DEN)
```

---

## 2. Parameters

| Name | Value | Meaning |
|------|-------|---------|
| `ORU_RES_TRANSFER_FEE_BURN_NUM` | `1` | Destroy numerator |
| `ORU_RES_TRANSFER_FEE_BURN_DEN` | `2` | Destroy denominator → **50%** of RES-transfer ORU fees |

Locked in `core/src/consensus/rigor_consensus_lock.h` via
`OruResTransferFeeBurnShare`. Changing the share is a consensus change.

**Why 1/2.** Keeps a miner incentive to include RES transfers (half the fee is
still claimable) while providing a material permanent sink. The absolute ORU
destroyed per block is market-determined: offsetting the 128 ORU/block subsidy
needs only modest average fee×volume (e.g. ~0.128 ORU destroyed per tx at
1000 RES transfers/block under a full-offset scenario).

---

## 3. Eligibility

A transaction contributes to `destroy_RES_transfer` iff it is a **RES transfer**:

```
GetTransactionInputAsset(tx, view) == ASSET_RES
```

(same predicate as `IsORBClaimTx` / dual-pool `CheckTxInputs_RES_DualPool`).

**Excluded** (no destroy share):

- Pure ORU spends
- Convergence (`RIGOR_MARKER_CONVERGE`, `0xbd`) — already destroyed via the converge path
- Body-tx mint — the `OP_CONVERGE` destroy is already destroyed via the converge path

Fee identity is unchanged: `fee_i = ORU_in − ORU_out` still holds in full.
Wallets still pay the full fee; only the miner’s claimable amount is reduced.

---

## 4. Consensus enforcement

| Site | Rule |
|------|------|
| `ConnectBlock` | Accumulate `nFeesOruResTransferBurn`; reject coinbase ORU if `> (nFeesOru − destroy) + subsidy` (`bad-cb-amount`) |
| `CreateNewBlock` | Set `vout[0].nValue = (nFeesOru − destroy) + subsidy` |

Underclaiming remains legal (additional voluntary destroy). Overclaiming is consensus-invalid.

Classification runs **before** `UpdateCoins` so prevouts remain visible.

---

## 5. Supply accounting note

`m_chain_oru_total` continues to track `S' = S + subsidy − converge`
(RFC-002 ledger path).
Fee destroys are UTXO-level destructions via the lowered coinbase cap and are **not**
folded into `m_block_converge_sum`. Circulating ORU is therefore strictly less than
or equal to the ledger scalar whenever fee destroys or voluntary underclaims occur —
the same asymmetry that already existed for unclaimed fees.

---

## 6. Activation

Genesis-active. No height / versionbits gate.

---

## 7. Non-goals

- Changing the RFC-020 mint predicate or the flat 128 ORU subsidy
- Destroying fees on ORU-only or mint transactions
- Parking destroyed ORU in an OP_RETURN output
