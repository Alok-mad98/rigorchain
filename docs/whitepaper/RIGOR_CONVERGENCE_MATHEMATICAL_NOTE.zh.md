# RIGOR Convergence 数学设计说明

**日期：** 2026-09-15  
**白皮书位置：** 附录 D（第四章、第五章的配套说明）

本文说明 Convergence 铸造的代数：`destroy_cost(h)` 如何变成整数谓词，该谓词为何不是价格预言机，RES 上限为何是导出的，以及公平对一条公开判定规则意味着什么。

- 一份 RFC

- 一次协议升级
- RFC-020、RFC-018、C++ 共识内核、Coq 模型或白皮书既有章节的替代

现行发行仍是 RFC-020。本文复述其中已经固定的恒等关系。它不改任何一个参数、任何一条谓词、交易序列化，或任何一字节共识。

## 1. 中心恒等

展示成本与共识谓词是同一条关系：

```
destroy_cost(h)

        ↓ 精确代数变换
          （精确的、保持整数的等价）

R · (2^25 + h)^2 ≤ B << 40
```

该变换是 **精确的、保持整数的等价**（exact integer-preserving equivalence）。它不是近似。它不使用：

- rounding（舍入）
- floor（向下取整）
- integer truncation（整数截断）
- discarded remainder（丢弃余数）

**展示辅助函数** 可以用整数除以 `2^50`（右移 50 位）求该商。该向下取整只供阅读。展示用的 rounding 与 floor **不进入共识**。共识从不除以 `2^50`。它计算 `B << 40`。把向下取整后的展示值倒填为 `B`，会把 floor 重新引进来。谓词不会这样做。

### 展示式

```
destroy_cost(h) = 1024 · (2^25 + h)^2 / 2^50
```

`2^50` 是 **曲线归一化分母**：`(2^25)^2 = 2^50`。它不是共识移位。共识从不右移 50 位。

单位：整枚 ORU / 整枚 RES。创世处恰好是：

```
destroy_cost(0) = 1024
```

同一展示成本的原子形式，是该量乘以八位小数标度 `10^8`：

```
destroy_cost_atoms(h) = 1024 · 10^8 · (2^25 + h)^2 / 2^50
```

### 原始 mint condition

记 `R` 为本笔铸造的 RES 原子，`B` 为同笔销毁的 ORU 原子，`h` 为确认高度。`RES_COIN = 10^8`。

当且仅当销毁的 ORU 按展示成本覆盖所请的 RES 时，铸造被承认。以整枚计：

```
(R / 10^8) · destroy_cost(h)  ≤  B / 10^8
```

等价的原子形式，且不求值展示商：

```
R · destroy_cost_atoms(h)  ≤  B · 10^8
```

这就是原始 mint condition。代入未消清的原子形式：

```
R · 1024 · 10^8 · (2^25 + h)^2 / 2^50  ≤  B · 10^8
```

本节其余部分在正有理数上消清该不等式。每一步都是两侧同乘或同除以一个正的非零整数，不等式方向与真值保持不变。没有丢项。没有丢余数。

### 消除 `10^8`

`10^8` 出现在不等式两侧。两侧同除以 `10^8`（`10^8 ≠ 0`）：

```
R · 1024 · (2^25 + h)^2 / 2^50  ≤  B
```

两种资产的小数标度已消除。它是单位换算，不是曲线本身的参数。

### 消除 `2^50`（曲线归一化分母）

`2^50` 是展示曲线的分母，不是共识移位。两侧同乘以 `2^50`（`2^50 ≠ 0`）：

```
R · 1024 · (2^25 + h)^2  ≤  B · 2^50
```

商 `/ 2^50` 已消除。共识从不计算这次除法。

### 消除 `2^10`

把创世成本写成 2 的幂：

```
1024 = 2^10
```

```
R · 2^10 · (2^25 + h)^2  ≤  B · 2^50
```

两侧同除以 `2^10`（`2^10 ≠ 0`）：

```
R · (2^25 + h)^2  ≤  B · 2^(50 − 10)
R · (2^25 + h)^2  ≤  B · 2^40
```

`1024` 作为写出的因子已消除。它的指数留在差 `50 − 10` 里。

### 把 `· 2^40` 改写为 `<< 40`（共识缩放因子）

`2^40` 是共识谓词的整数缩放因子，不是 `destroy_cost` 的分母。对非负整数 `B`，左移就是乘以 2 的幂：

```
B · 2^40  =  B << 40
```

该等式是非负整数左移的定义。它不是一种 rounding 模式。它不是对实数乘法的近似。

### 最终谓词

```
R > 0  →  R · (2^25 + h)^2 ≤ B << 40
R = 0  →  B 不受此谓词约束
```

`2^40` 是展示式消去 `1024 = 2^10` 之后的 **整数共识缩放因子**（`50 − 10 = 40`）。它不是 `destroy_cost` 的分母。展示分母仍是 `2^50`。

`R = 0` 是合法的纯销毁。正铸造当且仅当消清后的不等式在确认高度上成立时被承认。

消除 `10^8`、`2^10`、`2^50` 之后，原始条件的两侧与 `R · (2^25 + h)^2 ≤ B << 40` 是同一条整数关系。因此 `<< 40` 是原始 mint condition 的精确恒等变换。

`check_mint` 是精确的。没有需要规定的舍入方向。`destroy_cost(0)` 仍然恰好是 1024。

## 2. 整数共识的好处

共识求值的就是上一节的变换。被消去的因子不会再进入现场路径。

共识不需要：

- 除法
- 浮点
- 开方
- epoch 表
- 价格查找

只需要：

- 乘法
- 平方
- 移位
- 比较

一次乘法、一次平方、一次移位、一次比较。这就是铸造检查。

消清展示式中的商，现场路径不再做除法。关系保持为整数，不再需要浮点与开方。判定是 `(R, B, h)` 的封闭函数，不再需要索引 epoch，也不再需要查找价格。因此该机制的共识工作就是一条不等式的算术，而不是一套辅助表。

本文只陈述对本机制共识复杂度的这一降低。不与任何其他项目比较。

## 3. 为何共识缩放因子是 40

`RES_DESTROY_SHIFT = 40` 是整数共识缩放因子（`B << 40`）。它不是 `destroy_cost` 的分母。该分母仍是 `2^50`。

展示式是

```
destroy_cost(h) = 1024 · (2^25 + h)^2 / 2^50
```

该 **展示** 定义里的两个指数固定了共识缩放因子。它们不可与缩放因子互换：

```
1024 = 2^10                 创世整枚 RES 成本
(2^25)^2 = 2^50             曲线归一化分母
```

`2^50` 仍是展示分母。共识不按 50 移位。第 1 节按顺序消去它们：

```
50 − 10 = 40                整数共识缩放因子
```

因此：

```
RES_DESTROY_SHIFT = 50 − log₂(1024) = 40
```

缩放因子来自展示创世成本对展示分母的消去。换一个创世成本，`40` 跟着动，其余不变。改 `1024` 却不改缩放因子，或改极点（从而改 `2^50`）却不改缩放因子，恒等式会破：谓词就不再表示那条展示曲线。

因此 `40` 是强制的。它不是单独挑选的「好看的数」。它不是 `2^50`。

## 4. 为何这不是价格预言机

`destroy_cost(h)` 是：

- 协议工作要求（protocol work requirement）
- 确定性发行条件（deterministic issuance condition）

它 **不是**：

- 市场价格（market price）
- 汇率（exchange rate）
- 投资估值（investment valuation）

协议定义的是：确定性铸造 RES 所需的 ORU 销毁量。它不定义 RES 的市场价值。

确认节点求值的是 `(R, B, h)` 是否满足谓词。它不把 RES 标成某种外部单位，不发布二级比价，也不预测持有者能把铸出的数量卖成什么。若存在二级比价，那是外部观察，不是共识输入。

若二级比价高于协议销毁要求，套利可能铸造。若低于该要求，铸造可能停止。那些是市场对一条已公布条件的反应。不是协议在定价。

Convergence 曲线定义的是确定性的协议发行成本。
它不定义市场价格、盈利能力或未来需求。
不同高度之间的发行成本差异，不构成任何经济收益保证。

## 5. 为何 RES 上限是导出的，不是宣告的

数值

```
RES_MAX_SUPPLY = 2^22
```

不是治理参数。它不是一条事后必须靠计数器去守的独立存量。

它来自发行规则已经固定的三件事：

```
ORU 发行
        +
destroy_cost(h)
        +
理论上的最大销毁路径
```

记 `S = 128 = 2^7`（`h ≥ 1` 时每块 ORU 补贴），`P0 = 1024 = 2^10`（创世整枚成本），`H = 2^25`（极点）。则

```
destroy_cost(h) = P0 · (H + h)^2 / H^2
```

一块补贴在高度 `h` 最多能换到的 RES 是 `S / destroy_cost(h)`。该每块上限的封闭积分是

```
RES_MAX_SUPPLY = (S / P0) · H
               = 2^7 / 2^10 · 2^25
               = 2^22
               = 4 194 304 RES
```

理论上的最大销毁路径，是每一枚新发行的 ORU 在它出现的那个高度立即销毁。ORU 不能在存在之前被销毁，且 `destroy_cost` 严格递增，故 `1 / destroy_cost` 严格递减。任何延迟都只会得到更少 RES。没有任何囤积策略能从上方触及该界。

因此该上限是：

- 数学上界

它 **不是**：

- 挖矿承诺
- 日程保证

共识不主张有人会销毁每一枚补贴，不主张该界一定会被走满，也不主张实现存量等于 `2^22`。实现存量是 `ρ · 2^22`，其中 `ρ` 是终将被销毁以铸造 RES 的发行份额。`ρ` 是被观察到的，不是被设定的。

因此上限不需要全局发行计数器，也不需要治理参数。验证区块时对 `(R, B, h)` 求局部谓词。不必查询「至今已铸多少」。

## 6. 货币职能分离

发行路径是：

```
PoW
 |
 v
ORU
 |
 | destroy
 v
Convergence
 |
 v
RES
```

工作量证明产出 ORU。ORU 支付矿工，并作为流通资产转移。Convergence 在主体交易中销毁 ORU，并可以在整数谓词下铸造 RES。RES 不是区块奖励。

ORU 承担：

- 安全预算（security budget）
- 交易效用（transaction utility）
- 矿工支付（miner payment）

RES 承担：

- 稀缺储备资产（scarce reserve asset）
- 确定性发行（deterministic issuance）
- 非挖出（not mined）

分离存在，是因为一种资产不能同时最大化：

- 流通
- 稀缺
- 安全预算

被要求便宜流通的单位，被要求不要被持有。被要求稀缺的单位，被要求不要被花掉。被要求永远资助算力的单位，被要求在持有者停止交易之后仍支付矿工。这些压力若指派给同一原生存量，会互相冲突。

本文不主张这种分离会产生采用、价格或经济成功。它陈述协议所定义的指派：矿工支付与流通在 ORU；导出的稀缺在 RES；单向销毁是桥。

## 7. 公平

判定规则的公平是：

```
same (R, B, h)
      =>
same accept / reject
```

公平意味着：

- 同一公开输入
- 同一确定性结果

公平 **不** 意味着：

- 铸造数量相等
- 时点相等
- 经济结果相等

`R`、`B`、`h` 都在交易与确认区块里。没有第四个隐藏参数。

因此谓词不容许：

- 随机抽取（random selection）
- 矿工裁量（miner discretion）
- 矿池分配（pool allocation）

验证者对同一组公开输入重算 `R · (2^25 + h)^2 ≤ B << 40`，必须得到与其他验证者相同的对错。更早的高度有更低的单位销毁成本；那是已公布的日程，不是判定规则的缺陷。在不同高度铸造不同数量的参与者，会得到不同的实现数量。曲线许可这一点。那不是本文所说的公平。

## 8. 工程限度

当前对该整数谓词的验证使用 `unsigned __int128` 边界检查。`R` 受 `RES_MAX_SUPPLY` 约束，`B` 受 `MAX_MONEY` 约束，`h` 受 `INT32_MAX` 约束。在该盒子里，谓词左端约到 `2^110`，右端约到 `2^99`，对着 `unsigned __int128` 的 `2^128`。乘法、平方、移位落在该宽度内。

此类算术溢出论证证明的是：

- 有界整数安全（bounded integer safety）

它们 **不** 证明：

- C++ refinement
- 编译器正确性
- 已部署二进制的正确性

宽度事实与溢出断言，不证明 C++ 内核匹配 Coq 模型，不证明 `ConnectBlock` 已被 refinement，也不证明正在运行的二进制就是被检查过的那个对象。

```
equivalence_claimed = false
cpp_formal_equivalence = false
```

本文 **不主张**：

- 市场采用（market adoption）

### 设计语境

RIGOR 所沿用的，是更广泛的加密经济观察：不同货币职能若指派给同一种资产，可能产生互相冲突的压力。

这一讨论参考了既有工作，包括：

- Satoshi Nakamoto，《Bitcoin: A Peer-to-Peer Electronic Cash System》，2008。 <https://bitcoin.org/bitcoin.pdf>
- Nervos RFC-0015，《Crypto-Economics of the Nervos Common Knowledge Base》。
- Nakamoto 之后关于手续费安全预算的研究，其中包括 Miles Carlsten、Harry Kalodner、S. Matthew Weinberg、Arvind Narayanan，《On the Instability of Bitcoin Without the Block Reward》，ACM CCS，2016。

Bitcoin 引入了无需许可的工作量证明排序与基于 UTXO 的转移。后续研究把补贴下降之后的长期矿工支付，当作一个开放问题，而不是已经结算的结论。

RIGOR 并不复制那些模型。它把上述观察用于一套独立的双资产 UTXO 设计：ORU 承担流通与矿工支付；RES 承担导出的稀缺；Convergence 作为单向销毁—铸造桥。它不使用 state rent、state capacity，也不是智能合约资产平台。

这些文献只描述思想与研究语境。它们不蕴含协议继承、实现依赖、共识兼容或经济结果保证。

## 本文是什么

对一条恒等的数学设计说明：

```
destroy_cost(h)

        ↓ 精确的、保持整数的等价

R · (2^25 + h)^2 ≤ B << 40
```

变换是精确的。共识缩放因子是强制的。判定是公开的。上限是导出的。协议定义销毁要求；它不定义市场价值。这些都不是协议变更。
