# 第一章 — 双资产分离：ORU 与 RES 为何必须存在

本章说明 RIGOR **为何存在**。后文说明它如何运行。此处的主张是架构主张，不是市场预测。

一条公有工作量证明链必须同时完成三件事：

```
交换媒介（Medium of Exchange）
        +
价值存储（Store of Value）
        +
安全激励（Security Incentive）
```

典型的单资产设计——尤其是事先宣告有限总量的设计——强迫 **同一枚** 原生单位承担全部三项。这不是同一份工作。两类用户的时间视野、费用容忍度和交易动机截然不同。结果就是 **安全预算困境**：区块补贴结束后，长期享受安全的人并不是产生手续费、从而支付安全的人。

RIGOR 的回答不是指望价格永远上涨，也不是指望发行停止后手续费会自己出现。它是共识层上的 **资产分离**。ORU 承担交换与矿工支付，RES 承担稀缺。二者缺一不可。这对资产就是协议的存在原因。

---

## 1.1 两类用户，两种动机

**交换媒介** 是人们用来转移价值的单位。

MoE 用户把网络主要看作点对点价值转移系统。他们关心手续费的法币等价成本、确认速度，以及能否即时获得这枚资产来完成支付。他们对网络安全风险的暴露往往只有片刻。许多人从不把原生单位当作长期储备：支付服务可以在一次动作里买入、发送、卖出，发送方和接收方都不必持有长仓。对他们来说，资产必须 **流通**。价格水平和波动是次要的。他们不会自愿为一种自己几乎不消费的安全服务付费。

**价值存储** 是人们因为稀缺、规则稳定而愿意跨时间持有的单位。

SoV 用户把网络看作保护一枚稀缺原生存量的协议。转账只是进出该存量的通道。他们关心长期安全与去中心化：若链变得容易被攻击，存量就不再是价值存储；若验证与挖矿中心化，存量就带上对手方风险，不再具有独立价值。单次交易成本可以分摊到很长的持有期。流通是次要的。这些用户 **愿意** 为持续保护付费——但他们几乎不交易。

| 角色 | 时间视野 | 他们要什么 | 他们对矿工报酬的贡献 |
|------|----------|------------|----------------------|
| 交换媒介用户 | 分钟到小时 | 低费用、高频转移 | 手续费——但他们抵制高费用 |
| 价值存储用户 | 年 | 稀缺与永久保护 | 几乎没有交易，因而几乎没有手续费 |
| 矿工 | 每一块，永久 | 可预期的算力报酬 | 保护的是 **整条历史**，不只是当前块 |

于是同一枚单位被同时要求成为：

1. 人们愿意花出去的东西
2. 人们愿意长期持有的东西
3. 用来支付算力的东西

激励必然冲突。要让人「愿意花」，就与要让人「愿意长期持有并为之支付安全成本」相反对。

## 1.2 有限总量会把叙事锁死在价值存储上

事先宣告的硬顶并不只是限制发行。它 **选定一种叙事**。一旦市场把该单位定价为稀缺储备，理性持有者倾向于囤积而非使用。流转速度下降。本应在补贴消失后接棒的手续费市场，达不到安全预算所需的规模。

这有时被写成「劣币驱逐良币」。机制并不相同。古典格雷欣法则要求两种货币之间存在法定固定比价。这里只有一枚单位。流通被抑制，是因为 **升值预期**：同一件东西，持有比花掉更值。可观察的结果相似——「好钱」离开支付循环——但原因是 SoV 定价，而不是铸币比价。

更深的错配是时间维度。矿工算力保护的不只是今天的区块，而是此前所有区块的不可篡改性。价值存储用户在持有期间持续消费这种保护。一次性的入块费覆盖不了永久服务。要求 SoV 用户用「只有停止持有才会发生」的支付，去覆盖他们持续获得的安全，是激励不相容的。

---

## 1.3 两条路径，同一约束

Bitcoin 是单资产、有限总量设计的典范。它曾被要求成为交换媒介，也曾被要求成为价值存储。两条路径都看得见，失败的原因互补。它们是同一枚硬币的两面。

### 路径 A — Bitcoin 作为交换媒介

MoE 解读把 Bitcoin 网络主要视为点对点价值转移网络。真正提供价值的是交易本身，不是库存。用户不必持有：专门的支付服务可以即时买卖，发送方和接收方都不必建立长仓。这些用户不关心价格或波动，只关心交易费的法币等价成本。

若协议固定出块时间与区块大小（从而固定交易供给），网络成功必然推高交易成本，削弱它相对其他链及自身分叉的竞争力。

若试图用更快出块或更大区块来增加供给、压低费用，又会损害安全与去中心化：更高的孤块率、更高的验证成本、更少人能跑全节点。想要便宜转账的 MoE 用户，被要求接受一层更弱的结算。

### 路径 B — Bitcoin 作为价值存储

SoV 解读把 Bitcoin 网络视为为其原生资产提供安全保护的协议，使其能长期保值。MoE 只是进出该资产的必要通道。长期持有者不太关心单次交易成本，但非常关心价值，而价值取决于安全与去中心化：

- 若网络变得不安全、易被攻击，它就不再被视为价值存储，资产会失去独立定价；
- 若网络中心化，该资产就不再具有独立价值，而须承担对手方风险。

这条路径要成功，必须保持货币政策稳定，并维持安全与去中心化。但 Bitcoin 有硬顶。全部币挖完后，矿工只能靠交易费。这是否可持续仍是开放问题——尤其因为成功的 SoV 文化本身往往产生不了多少交易。手续费占矿工收入的比例，在很长时期内都远低于区块奖励。硬顶之后的假设是：手续费会长到足以替代发行。这一假设不是协议规则。它是一种希望。

### 同一枚硬币

试图用大区块强迫走路径 A，并不能逃出路径 B。总量仍然有限，市场仍会赋予它一定的储备溢价。于是这枚单位被定价为「想成为现金、又不像数字黄金」：既没有形成足够大的真实转账需求来填满多出来的区块空间，又因「更像现金、更不像储备」而被持续估值折价。手续费依然起不来。安全预算同样成问题。空荡荡的区块空间是症状，不是另一种病。

```
有限总量 + 单一资产
        │
        ├─ 强化稀缺  →  囤积  →  手续费稀薄  →  补贴结束后的安全缺口
        │
        └─ 强化吞吐  →  SoV 溢价被削弱
                       + 总量仍然有限
                       →  既没有够用的手续费市场
                          也没有干净的储备叙事
```

单资产加有限总量，无法同时做到「让人愿意花」和「让人愿意持有几十年」。要么交易不足，手续费撑不起安全；要么为了刺激交易而削弱稀缺性，最终两者都落空。

## 1.4 长期谁来补偿矿工

安全与去中心化代价高昂。必须支付给网络运营者，每一块都要付，而且没有一个「需求结束」的日历。

在单资产、纯手续费模型里：

- MoE 用户对安全风险的暴露时间极短，因此不愿为此付费；
- SoV 用户有长期暴露，因而是自然的付费方——但他们几乎不产生交易。

范畴错误在于：用 **即期** 支付（一笔交易的入块费）去资助一种 **流量** 商品（对历史的持续保护）。对价值存储网络而言，通胀型区块奖励才是激励相容的工具：持有者按享受服务的时长，通过接受手中单位被稀释，间接向安全提供者付费。

把这一工具放在 **同一枚** 本应作为价值存储的单位上，会毁掉价值存储叙事。完全不放在任何单位上，补贴结束后矿工无人支付。这是单资产、有限总量无法同时占据的三角形：

```
              廉价流通
                 / \
                /   \
               /     \
          有限稀缺   永久矿工预算
```

三选二。Bitcoin 选择有限稀缺，并希望第三个顶点以手续费的形式出现。在同一代码上永久增发，是选择矿工预算并放弃储备。RIGOR 拒绝在同一代码上三选二。它把三个顶点分给两枚资产，再用销毁—铸造把它们耦合起来。

## 1.5 分离 — RFC-020

**ORU** 是交换媒介，也是矿工支付资产。

- 平坦补贴：`subsidy(0) = 0`，`subsidy(h ≥ 1) = 128` ORU。没有减半。ORU 不设宣告上限。
- 通胀 **速率** 按 `1/t` 衰减，永不达到零。剩余通胀的 **水平** 不是一张时间表，而是 `1 − ρ`，其中 `ρ` 是已被销毁以铸造 RES 的发行份额。
- ORU 的唯一职责是日常流通、手续费，以及今天就付给算力的现金流。用户可以放心使用它，而不必担心「花掉就损失一枚储备仓位」。当且仅当市场对价值存储产生真实需求时，ORU 才会被销毁，流通量下降。硬度是需求的函数，而不是创世时写死的上限。

**RES** 是价值存储。

- RES 不能被挖出。Coinbase 从不创造它。禁止反向兑换（RFC-020 §6）。
- RES 只能在一笔主体交易里诞生：销毁 ORU（`OP_CONVERGE`），并在同一笔交易中铸造 Witness v1 RES，当且仅当

  ```
  R > 0  →  R · (2²⁵ + h)² ≤ B << 40
  ```

  展示式：`destroy_cost(h) = 1024 · (2²⁵ + h)² / 2⁵⁰` ORU / 整枚 RES。创世成本为 1024 ORU / RES。该成本随高度严格递增。
- 单位成本随确认高度上升，因此早期铸造者为更长的剩余保护期支付更低的单位成本，晚期铸造者支付更高成本。这是按享受安全服务的时长成比例付费，编码为高度函数，而不是对 RES 余额的经常税。
- 上限 `RES_MAX_SUPPLY = 2²² = 4 194 304` RES 是每块铸造上限的导出上界 `(S / P0) · H`。它不是事先宣告的「2100 万」式参数。它 **不需要共识计数器**：因为 `destroy_cost` 严格递增，任何延迟销毁都只会得到更少 RES。没有任何囤积策略能从上方突破该界。实现存量等于 `ρ · 2²²`。上限是硬约束，不是「一定会被填满」的承诺。

二者的耦合是一套机制，不是两枚孤立的代码：

```
算力                      →  ORU 补贴（每块 128）
触及上限的 RES 需求        →  销毁 ORU            （RFC-020）
RES 转账                  →  销毁部分 ORU 手续费  （RFC-018，一半）
ρ                         →  实现的 RES 存量，以及剩余的 ORU 通胀
```

`destroy_cost(h)` 是协议销毁要求，不是市场报价。铸造开放期间，二级市场 RES/ORU 比值若高于该要求，会被铸造套利拉回。低于该要求，铸造停止。

## 1.6 分离之后

囤积被隔离在 RES 上，不再抑制 ORU 的流通与费用市场。

ORU 可以独立发展吞吐与费用市场，而不必与同一单位上的储备叙事竞争。花掉 ORU，并不是花掉稀缺存量。

矿工预算在效用资产上有协议地板——每块 128 ORU——不依赖于 SoV 持有者是否交易。当 RES 需求出现在铸造上限附近，该需求就是 ORU 的汇：剩余通胀下降，ORU 硬度内生上升。单资产回路

```
交易减少 → 手续费变薄 → 安全变弱 → 进一步囤积
```

被替换为需求驱动的耦合。协议不创造需求。它把已经存在的需求，转换成被销毁的 ORU 和被支付的矿工。

两类用户不再互相拖累。他们在 Convergence 相遇：MoE 用户保有一枚可以花的单位；SoV 用户以销毁 ORU 的方式，按随高度上升的成本进入一枚永不增发的存量。

ORU 解决「交易量不足」。RES 解决「补贴结束后安全预算不可持续」。单独任一枚都不完整：

| 若只有 ORU | 若只有 RES |
|------------|------------|
| 永久的工作报酬，没有稀缺存量，也没有来自储备需求的内生硬度 | 有上限的存量，没有工作报酬资产，无法支付算力 |
| 有交换媒介，没有价值存储 | 有价值存储，没有安全预算 |

这对资产不是单链上的可选优化。它是单资产结构性缺陷的必要出路——这是本协议的存在原因。

---

## 1.7 本章不主张什么

- 不为任一资产设定外部价格目标。
- 不断言 `ρ` 会很高。RES 的终身发行量仍随参与率从接近零到 `2²²`（RFC-020 §8）。
- 不断言上线第一天就存在 RES/ORU 二级市场。即便 `ρ = 100%`，第一年至多大约 6 564 RES。薄到发现不出任何比价的市场，无法把 RES 需求传导为 ORU 销毁。这是采纳风险，不是共识漏洞。
- 不主张 C++ 实现与内核模型形式等价。

**RIGOR 的回答不是市场承诺。它是共识层上的资产分离。** 第二章给出实现这一分离的规则。
