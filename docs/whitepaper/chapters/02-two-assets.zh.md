# 第二章 — 规则与参数：分离如何写进共识

第一章把三个顶点分给两枚资产。本章把那一分离写成冻结规则。此处的主张仍是架构主张：协议固定的是 **变换**，不是价格，也不是参与率。

```
算力发现与排序
        ↓
ORU 进入流通（coinbase，每块 128）
        ↓
销毁 ORU（OP_CONVERGE）
        ↓
同一笔主体交易可以铸造 RES
```

工作量证明提供公开可验证的高度顺序，并使重写成本随累计工作量增加。它 **不** 创造 RES。没有 Convergence，就没有新的 RES。

---

## 2.1 一套机制，不是两枚孤立代码

第一章的三角形要在这一架构下同时成立，两枚资产由一条单向变换拴在一起。若它们可以自由兑换，就会削弱两种货币职能之间的预定分离。若它们互不相关，矿工预算与稀缺存量就再次脱节。

协议只承认这一条路：

```
工作 → ORU
ORU 销毁 →（可以）RES
RES → ORU    非法
```

`destroy_cost(h)` 是协议销毁要求，不是市场报价。铸造开放期间，二级市场 RES/ORU 比值若高于该要求，会被铸造套利拉回；低于该要求，铸造停止。协议不发布牌价，它发布的是确认高度上的销毁成本。

| 角色 | 资产 | 冻结职责 |
|------|------|----------|
| 交换媒介、手续费、矿工现金流 | **ORU** | 流通；永久补贴；Convergence 的唯一输入 |
| 协议内设计的价值存储职能 | **RES** | 有限存量；只能由销毁 ORU 诞生；永不反向兑换 |

用户 **挖的是 ORU**。用户 **销毁的是 ORU**。同一笔交易 **可以** 铸造 RES。这句话不能缩短成「挖 RES」。

---

## 2.2 ORU — 流量的规则

ORU 承担第一章里被设计为无限期支付的那个顶点：矿工预算。它也是协议内的日常交换媒介。因此它的发行被设计为可预期、不减半至零，且不宣告硬顶——硬顶会把 SoV 叙事重新锁回这枚流量资产上。

```
subsidy(0) = 0
subsidy(h) = 128 ORU          对每一个 h ≥ 1
```

| 项目 | 冻结规则 | 为何如此 |
|------|----------|----------|
| 脚本路径 | Witness v0 | 分类即身份，不是登记表 |
| 单位 | `1 ORU = 100 000 000` 原子 | 与 RES 同一小数位，便于整数算术 |
| 创世补贴 | `0` | 高度 0 不发补贴 |
| 此后每一块 | `128 = 2⁷` ORU | 矿工预算的协议地板，与 RES 需求、手续费无关 |
| 减半 | 无 | 减半会把安全支付重新交给手续费市场的结果 |
| 宣告上限 | 无 | 硬度被设计为内生于 `ρ`，而不是事先写成一个数 |

供给定律：

```
S_ORU(h+1) = S_ORU(h) + R(h+1) − C(h+1)
```

`R(h)` 是该块补贴。`C(h)` 是该块 Convergence 销毁。被销毁的 ORU 离开流通。它不会 1:1 变成 RES。

通胀 **速率** 按 `1/t` 衰减：第 100 年约 1.00%，第 1 000 年约 0.100%，单调趋向零，永不达到零。剩余通胀的 **水平** 不是时间表，而是 `1 − ρ`。在协议模型下，`ρ = 100%`——每一枚新发行的 ORU 都被销毁以铸造 RES——对应于流通中的 ORU 供给恒定。固定上限并不能表达这一安全支付目标，所以 ORU 不设上限。

最低销毁承诺：`nValue > 0` 的一枚原子即可构成合法的纯销毁。创世高度铸造 1 枚 RES 原子所需的最小销毁是 1 024 枚 ORU 原子。

ORU 被设计来流动。花掉它，并不是花掉稀缺存量。

---

## 2.3 RES — 存量的规则

RES 被设计为协议内的价值存储资产。它承担被设定为保持稀缺的那个顶点。因此它不能被挖出，不能被治理增发，不能与 ORU 1:1 兑换，也不能反向兑回。它只在一笔主体交易里诞生：销毁 ORU，并在同一笔交易中铸造 Witness v1 RES。

共识从不计算展示式。它计算消去除法后的同一关系：

```
R > 0  →  R · (2²⁵ + h)² ≤ B << 40
R = 0  →  B 不受此谓词约束          纯销毁合法
```

`R` 是本笔铸造的 RES 原子，`B` 是唯一 `OP_CONVERGE` 输出里的 ORU 原子，`h` 是确认高度。展示式仅供阅读：

```
destroy_cost(h) = 1024 · (2²⁵ + h)² / 2⁵⁰
destroy_cost(0) = 1024 ORU / 整枚 RES
```

`2⁵⁰` 是 `destroy_cost(h)` 的曲线归一化分母，不是共识移位。`B << 40` 中的 `2⁴⁰` 是消去 `1024 = 2¹⁰` 之后的整数共识缩放因子，不是 `destroy_cost` 的分母。展示辅助函数可以按 `2⁵⁰` 做整数除法向下取整；该 rounding/floor 不进入共识。

`R = 0` 是合法的纯销毁：ORU 被移除，不铸造 RES。`R > 0` 时，不等式不成立则整笔交易无效。

| 项目 | 冻结规则 | 为何如此 |
|------|----------|----------|
| 脚本路径 | Witness v1 | 与 ORU 分类隔离 |
| 单位 | `1 RES = 100 000 000` 原子 | 与 ORU 对齐 |
| 诞生 | 主体交易销毁—铸造，永不在 coinbase | 挖矿支付的是流量，不是存量 |
| 接收者 | 该笔交易的 RES 输出，**不是** 矿工 | 矿工卖的是排序与安全，不预支储备 |
| 预挖 / 行政铸造 | 无 | 入口必须付出可验证的 ORU 销毁 |
| 反向兑换 | 非法 | 否则预定的职能分离会被削弱 |
| 每块铸造上限 | 无 | 需求应当能在单块内被全部吸收 |
| 铸造成熟 | 100 块 | 重组保护 |
| 上限 | `2²² = 4 194 304` RES | 推导得出，见 2.4 |

```
S_RES(0) = 0
S_RES(h+1) = S_RES(h) + body_mint_atoms(h+1)
S_RES(h) ≤ 419 430 400 000 000 原子
```

成本随高度 **严格递增**。这不是装饰。它做两件事。第一，把第一章的「按时长付费」写成高度函数。这形成一套对持有时长敏感的成本日程：更早参与者获得更低的协议定义销毁成本，因为它在高度时间线上更早锁定资本。因此更早的铸造者为更长的剩余保护期支付更低的单位成本。第二，它使上限不需要共识计数器——见下一节。

是否发生铸造，由需求决定。**若** 发生，成本是高度的纯函数，不是市场报价，也不随难度移动。

## 2.4 参数从哪里来

主要发行常数选取为 2 的幂，以便简化算术核验。上限是其中三个的乘积，因此上限的推导直接来自指数关系：

```
RES_MAX_SUPPLY = Σ_{h≥0} S / destroy_cost(h)
               = (S / P0) · H
               = 2⁷ / 2¹⁰ · 2²⁵
               = 2²²
               = 4 194 304 RES
```

`S = 128`，`P0 = 1024`，`H = 2²⁵ = 33 554 432` 块（约 638 年）。指数恰好为 2，封闭式才恰好是 `(S / P0) · H`，没有余项，上限才落在 2 的幂上，而不是落在附近。改动其中任一常数，可见的恒等式就会破，而不是悄悄平移一条曲线。

`RES_DESTROY_SHIFT = 40` 不是独立选取的。它是整数共识缩放因子（`B << 40`），由创世成本 `1024 = 2¹⁰` 对展示分母 `2⁵⁰` 的消去强制推出。它不是 `destroy_cost` 的分母：

```
R · 1024 · (2²⁵ + h)²  ≤  B · 2⁵⁰
R · (2²⁵ + h)²         ≤  B · 2⁴⁰
```

因此 `40 = 50 − log₂(1024)`。换一个创世成本，缩放因子跟着动，其余不变。`2⁵⁰` 仍是展示曲线分母。

**为何这是上界，且不需要共识强制执行。** 任意高度前被销毁的 ORU，不能超过当时已经发行的 ORU。`destroy_cost` 严格递增，故 `1 / destroy_cost` 严格递减。标准交换论证给出：使 RES 总量最大的策略，是每一枚 ORU 在它出现的那个高度立即销毁。该策略的总和就是上面的封闭式。延迟销毁只会得到更少 RES。没有任何囤积策略能从上方触及该界。验证区块时不必查询累计计数器。

到任意高度的累计上限也有封闭形式：

```
cumulative(h) = RES_MAX_SUPPLY · h / (h + 2²⁵)
```

极点 `h = 2²⁵` 的操作含义是：在 `ρ = 100%` 时，发行分布的中位数恰好落在第 638 年。那一年累计 RES 为上限的一半，销毁成本约为 4 096 ORU / RES。

实现存量等于参与率乘以上限，不多也不少：

| ρ | 实现发行 | 利用率 |
|--:|--------:|------:|
| 5% | 209 715 RES | 5.0% |
| 20% | 838 861 RES | 20.0% |
| 50% | 2 097 152 RES | 50.0% |
| 100% | 4 194 304 RES | 100.0% |

铸造在整块补贴买不起 1 枚 RES 原子时结束。整数算术给出的高度是 `118 599 277 598`（约公元年后 2 254 957 年）。这是参数的推论，不是另设的参数。

## 2.6 第二条汇 — RFC-018

RFC-020 规定 RES **诞生** 的协议成本。RFC-018 在 RES **流转** 时继续吸收 ORU。两条汇不混成一个「供给」数字。

RES 转账的网络费仍用 ORU 支付。其中一半不可被 coinbase 领取，永不进入 UTXO 集，因而被销毁：

```
destroy_RES_transfer = Σ floor(fee(tx) · 1 / 2)
```

另一半仍归矿工，以保持打包 RES 转账的激励。纯 ORU 花费、Convergence 本身、主体铸造——这三类不走这一半。Convergence 已经在 `OP_CONVERGE` 路径上销毁过了。

分开记账的四个 ORU 量：

| 量 | 它是什么 | 它不是什么 |
|----|----------|------------|
| ORU 账本供给 | 已发行补贴减去 Convergence `C(h)` | 流通 UTXO、费用销毁、钱包余额 |
| 流通 UTXO | 仍在 UTXO 集中可花费的 Witness v0 ORU | 账本路径、已销毁量 |
| Convergence 销毁 | 进入不可花费 `OP_CONVERGE` 的 ORU | 费用销毁 |
| 费用销毁 | RES 转账中不可领取的那一半 ORU 费 | Convergence `C(h)`，也不是一枚销毁 UTXO |

浏览器可以分别展示这四项。它们都不是全局资产状态表。共识不维护一张「总供给」登记。

## 2.7 两枚资产在账本上的出生地

| | **ORU** | **RES** |
|--|---------|---------|
| 职责 | 算力报酬、手续费、Convergence 输入 | 独立的稀缺存量 |
| 分类 | Witness v0 | Witness v1 |
| 账本起源 | Coinbase 补贴 `R(h)` | 主体交易销毁—铸造 |
| 每块 | 128 ORU（`R(0) = 0`） | 谓词允许的任意 `R` |
| 谁收到 | 矿工 | 该笔交易的 RES 输出，不是矿工 |
| 上限 | 无宣告硬顶 | 推导出的 `2²²` RES |
| 日历 | 补贴是高度函数 | 成本是高度函数；是否铸造不是 |

**协议强制执行：** 铸造必须满足谓词，否则交易无效；`S_RES` 不得超过推导上限（运行时防御；§2.4 表明它不可达）。

**协议不保证：** 有人会销毁 ORU；上限会被填满；二级市场会存在；`ρ` 会落在某一个区间。

---

## 2.8 本章不主张什么

- 不为任一资产设定外部价格。`destroy_cost(h)` 不是牌价。
- 不断言 `ρ` 会高，也不断言时间表会被走满。
- 不断言上线初期存在可用的 RES/ORU 二级市场。
- 不把四个 ORU 量折叠成一个「流通量」故事。
- 不主张 C++ 实现与内核模型形式等价。Coq 模型证明选定不变量（含 ORU 折合恒等式 `n · 128`）；它不证明 `ConnectBlock`。

**规则固定的是变换。需求是否到来，不是规则。** 第三章说明这两枚身份如何作为原生 UTXO 脚本存在于账本上——不是登记表，不是覆层。
