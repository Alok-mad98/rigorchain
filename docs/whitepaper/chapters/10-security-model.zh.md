# 第十章 — 安全模型与威胁边界

第一至九章给出了双资产规则、验证动作与形式化边界。本章说明协议被设计为检测哪些失效，以及哪些风险仍在共识之外。

此处的主张仍是架构主张。协议定义 **检测与拒绝条件**。它不主张攻击不会发生，不主张算力无法改写近期历史，也不主张市场参与会资助安全。

```
全节点验证
        ↓
承认合法状态迁移
        或
拒绝非法状态迁移
        ≠
攻击面为空
        ≠
外部系统落入共识范围
```

---

## 10.1 共识攻击边界

全节点验证被设计为拒绝非法状态迁移。下列情形已由现行拒绝码与分类规则命名（RFC-020，第三至四章）。本节不增加规则。

| 情形 | 协议响应 |
|------|----------|
| 非法 RES 铸造 | 谓词 `R > 0 → R · (2²⁵ + h)² ≤ B << 40` 不成立，交易无效 |
| 缺少 `OP_CONVERGE` | `bad-txns-res-mint-no-burn`：有 RES 输出而无可见销毁 |
| 欠付 RES 铸造 | `bad-txns-res-mint-underpaid`：销毁不足以覆盖所请的 `R` |
| 非法 RES → ORU 兑换 | `illegal-res-to-oru-conversion`：反向路径，或花费 Convergence 输出 |
| 非法资产分类 | 封闭模板：未列入的脚本形状不被接受为新的货币输出 |
| 链重组 | 最多工作量顺序；铸造与 coinbase 成熟 100 作为重组保护 |

重组仍可能发生。协议不主张：在足够算力下历史不可被改写。成熟 100 是与 coinbase 相同的确认深度约定。它不是该深度上重组不可能的证明。

欠付铸造即便已被矿池或探索器显示为入账，仍属无效。展示并不承认一次状态迁移。见第七章。

---

## 10.2 经济攻击边界

协议规定转换机制。它不保证市场参与。

| 压力 | 协议做什么 | 协议不做什么 |
|------|------------|--------------|
| ORU 通胀压力 | 剩余通胀水平为 `1 − ρ`；若发生销毁，硬度由需求驱动 | 保证 `ρ` 很高，或保证 ORU 有终端上限 |
| RES 需求不足 | 铸造不发生；`S_RES` 低于导出上界 | 创造 RES 需求 |
| 销毁参与不足 | 实现存量为 `ρ · 2²²`；上限是上界 | 填满上限 |
| 手续费市场偏弱 | RFC-018 销毁 RES 转账 ORU 费的一半；ORU 补贴仍为 128 | 保证手续费市场能替代发行 |
| 矿工激励压力 | 创世后每块 coinbase 支付 128 ORU | 保证这 128 ORU 的外部购买力 |

协议单位上的安全预算有地板。外部单位上的安全预算没有。矿工是否认为该 ORU 报酬足够，是市场结果。

---

## 10.3 外部依赖边界

下列事项在共识之外，这与第八、九章已经划定的边界一致：

- 钱包软件正确性与交互
- 用户密钥保管
- 网络连通与 P2P 诚实
- 硬件可靠性与侧信道
- 第三方服务（矿池、探索器、网站、索引器）

全节点可以拒绝非法块。它不能使被盗密钥无法花费、使断连的对等方变得诚实，或使探索器的展示成为权威。Coq 模型的形式化验证不覆盖这些表面，也不证明正在运行的 C++ 二进制。

---

## 10.4 假设与限度

这不是一份缺陷清单。它是明确的模型边界。

协议不证明：

- 诚实多数
- 网络行为
- 硬件可用性
- 市场采用
- 汇率
- 钱包安全
- 编译器正确性

那些仍是假设或外部事实。10.1 的检测与拒绝条件仍在模型内部适用。它们不把上列事项变成定理。

---

## 10.5 本章不主张什么

- 不主张所列攻击不会发生。
- 不主张与 Bitcoin 的安全性比较。
- 不主张 128 ORU 构成足够的现实世界安全预算。
- 不主张 C++ 与内核模型等价。
- 不增加拒绝码、成熟规则，或超出前文章节的算力假设。

**协议定义检测与拒绝。它不定义市场需求。** 第十一章说明这一架构有意不提供什么。
