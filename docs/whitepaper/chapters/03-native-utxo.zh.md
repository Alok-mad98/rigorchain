# 第三章 — 原生 UTXO：两枚身份如何存在于账本上

第二章把三个顶点写成冻结规则。本章说明那两枚身份如何作为账本对象存在。此处的主张仍是架构主张：协议固定的是 **对象与分类**，不是一张链外登记表，也不是覆在单一 UTXO 上的颜色。

若 ORU 与 RES 只是同一枚输出上的注释，第一章的分离就没有发生。注释可以被忽略、被索引器改写、被另一套合约重新合成。分离是每一个全节点从同一串字节读出的同一分类。

```
TxOut = (nValue, scriptPubKey)
scriptPubKey 的形状  →  资产身份
共识谓词            →  这枚输出是否合法诞生、能否被花费
```

---

## 3.1 为何身份是原生的

覆层更容易。给一枚已有 UTXO 涂色、在旁链记一张余额表、用合约再发行一枚「储备」，都不必改共识。那也是双资产设计少见的原因：解释一套代码、列一张表、只维护一种 UTXO，更便宜。

便宜的代价是重新打开第一章的激励张力。若两枚身份不在共识里，矿工预算与稀缺存量可以在账本外重新绑回同一对象。登记表可以在无人销毁 ORU 的情况下记上一笔 RES。铭文可以把 SoV 叙事贴回 MoE 单位。合约账户可以把兑换做成双向。

因此协议不采用三条捷径：

| 捷径 | 它看起来像什么 | 它破坏什么 |
|------|----------------|------------|
| 登记表 | 全局 `(资产, 余额)` 或发行名单 | 全节点必须相信表，而不是重放字节 |
| 覆层 | 颜色、铭文、符文、包装资产 | 同一枚 UTXO 仍是一枚单位；分离只存在于索引器 |
| 通用虚拟机 | 任意合约再定义「ORU / RES」 | 身份可被合约改写；验证面不再封闭 |

RIGOR 接受更难的公开故事——两枚原生身份、一条单向变换——以便交换媒介职能与价值存储职能不被指派给同一个共识对象。

---

## 3.2 账本对象仍是 UTXO

节点谱系来自 Bitcoin。一笔未花费输出仍是：

```
TxOut = (nValue, scriptPubKey)
```

没有作为共识真相的账户模型。`CTxOut` 上没有并行的 `asset` 字段。没有 `(资产, 面额, 脚本)` 三元组。所有权只通过花费旧输出、创造新输出而改变。

```
上一枚 UTXO
        ↓
交易验证（分类、签名、隔离、铸造谓词）
        ↓
新的 UTXO 所有者
```

没有隐藏余额。没有全局可变账户状态。全节点不必查询外部登记表，就能知道一枚输出是什么、谁可以花费它。

同一串被接受的区块字节，必须得到同一有效性判定。

---

## 3.3 脚本分类身份，共识裁定合法性

资产身份不是外部元数据。`scriptPubKey` 被解析为见证程序。见证版本与程序形状把输出分为 ORU、RES，或（零值 `OP_RETURN`）无资产。分类函数是 `AssetTypeFromScriptPubKey`。分类对共识可见。

```
脚本形状
        ↓
AssetTypeFromScriptPubKey
        ↓
ORU  |  RES  |  NONE  |  INVALID
```

更早的简称「脚本就是资产」正确地禁止了并行资产字段。精确规则是：**脚本定义身份；共识定义合法性。** 解析出 Witness v1，并不等于这枚 RES 被合法铸造。RES 的诞生仍须同一笔交易里的 `OP_CONVERGE` 销毁，以及

```
R > 0  →  R · (2²⁵ + h)² ≤ B << 40
```

脚本是合规 / 分类层。它声明一枚输出可以存在、以及稍后如何被花费。所有权与转移通过 UTXO 消耗、谓词验证和签名强制执行。脚本单独不授权创造资产。

这避免三件事：隐藏的资产元数据、对外部索引的依赖、两台机器对「这是什么」给出不同答案。

---

## 3.4 封闭模板

生产节点 **没有脚本虚拟机**。没有 `EvalScript`，没有 `interpreter.cpp`。字节被分类，花费走 `VerifyRigorPredicate`。活着的模板是一份封闭清单：

| 脚本形状 | 分类 | 资产 | 可否花费 | 它是什么 |
|----------|------|------|----------|----------|
| Witness v0，20 字节程序 | `WITNESS_V0_KEYHASH` | ORU | 是 | 日常持有与转移 |
| Witness v1，32 字节程序 | `WITNESS_V1_RES` | RES | 是 | 稀缺存量 |
| `<20 字节 HASH160> 0xbd` | `CONVERGE` | ORU | **否**（不进入 UTXO 集） | 销毁容器，铸造输入 |
| 零值 `0x6a`（仅推数据） | `NULL_DATA` | NONE | 否 | 数据载体 |
| 其余一切 | `NONSTANDARD` | INVALID | — | 共识无效 |

Coinbase 上的 `<maturity> <HASH160> 0xbb` **不是** RFC-020 的铸造路径。RES 不从 coinbase 诞生。

在生产协议配置中，P2PKH、P2SH、P2WSH、Taproot 与 secp256k1 花费路径不被接受为新的货币输出。裸多签与未知见证版本同样不被接受。花费签名只有 Ed25519。

**Witness v1 不是 Bitcoin Taproot。** 它复用了 BIP141 的版本字节，作为原生 RES 容器。没有控制块、没有 annex、没有 tapscript。共享一个版本号，不是共享一套虚拟机。

清单封闭，是为了让每一个诚实节点承担得起验证责任。多一条可执行能力，就多一份共识责任。

---

## 3.5 资产池隔离

守恒按 **资产池** 执行。这不是钱包约定。

```
ORU 输入  不能  资助 RES 输出
RES 输入  不能  资助 ORU 输出
RES → ORU 兑换    非法
```

唯一打破「ORU 不能变成 RES」的路径，不是转账，而是第二章的单向变换：同一笔主体交易销毁 ORU，并在谓词成立时铸造新的 Witness v1 RES。被销毁的 ORU 离开流通，并不 1:1 改名。新的 RES 是一枚新的 UTXO，不是旧输出上的颜色。

`OP_CONVERGE` 输出本身分类为 ORU 域：不可花费，验证后不插入 UTXO 集。它声明销毁量 `B`，供铸造算术使用。每笔交易至多一个正值 Convergence 输出，且只能来自 ORU 输入。

---

## 3.6 不是登记表，不是覆层

| | 登记表 / 合约账户 | 颜色 / 铭文 / 符文 | RIGOR |
|--|-------------------|---------------------|-------|
| 身份存在何处 | 全局表或合约存储 | 索引器对同一 UTXO 的注释 | `scriptPubKey` 的形状 |
| 全节点如何知道 | 读表或跑合约 | 依赖外部解析 | 分类同一串字节 |
| 能否在无人销毁的情况下「出现」RES | 可以（表被改写） | 可以（只改注释） | 不可以 |
| 两枚身份是否同一共识对象 | 常常是 | 是（底层仍是一枚单位） | 否：v0 与 v1 是两个池 |
| 验证面 | 随合约增长 | 随索引规则增长 | 封闭模板 + 整数谓词 |

ORU 与 RES 不是：染色币、Bitcoin 铭文、Ordinals、Runes、智能合约代币、包装资产、外部记账层。它们是 RIGOR UTXO 系统内的两枚原生身份。任一枚都不是另一枚的二次表示。不存在父—子资产关系。二者处于同一协议层，由分类与隔离分开，由 Convergence 单向耦合。

> ORU 与 RES 是两枚原生资产身份。分离发生在共识里，而不是发生在浏览器里。

---

## 3.7 花费：分类之后的谓词

花费不解释任意字节码。节点确认输入属于哪一池，再对应该池的谓词：

| 身份 | 花费模型 |
|------|----------|
| ORU（Witness v0，20 字节） | 两项见证；程序是 `HASH160(公钥)`；CHECKSIG 为 Ed25519 |
| RES（Witness v1，32 字节） | 两项见证 `<签名, 32 字节公钥>`；公钥必须等于程序本身 |
| Convergence | 不可花费；不进入 UTXO 集 |
| `OP_RETURN` | 不可花费；面额必须为 0 |

签名域与 Bitcoin 默认路径分离。没有 `SigVersion::BASE`。没有作为共识花费路径的 P2PKH 模板。

内核模型证明分类器的值域、划分、以及按类的可花费性（抽象 `sig_ok`）。那不是虚拟机，也不是 Ed25519 不可伪造性证明。

---

## 3.8 能力收窄是验证的前提

本章不与可编程平台竞赛。货币完整性不要求无限可编程。更多执行路径会扩大验证面。更小的执行面带来更强的验证能力。

```
更少能力
        ↓
更少复杂度
        ↓
更小攻击面
        ↓
更可做的数学验证
```

目标不是最大可编程性。目标是最大可验证性。脚本存在，是为了检查所有权与资产身份。脚本不存在，是为了让账本变成一台通用计算机。

更细的模板清单与安全边界见独立工程章 [`RIGOR_MINIMAL_SCRIPT_ARCHITECTURE.md`](./RIGOR_MINIMAL_SCRIPT_ARCHITECTURE.md)。那一章是实现审计，不是另一套经济主张。

---

## 3.9 本章不主张什么

- 不主张 C++ 与内核模型形式等价。
- 不主张 Ed25519 在内核里被证明不可伪造。
- 不把「最小脚本」写成「没有脚本」。字节仍被分类，花费仍走谓词。
- 不把 Witness v1 写成 Bitcoin Taproot。
- 不把 Convergence 写成智能合约。它是销毁容器；铸造算术是下一章的主题。

**身份在脚本里。合法性在共识里。** 第四章说明 Convergence 如何作为那条单向桥被验证——销毁是可见的，铸造是同一笔交易里的整数谓词，不是 1:1 柜台。
