# 第九章 — 产品表面：展示仍是展示

第八章划清了模型与正在运行的二进制。本章说明人如何看见并参与那套规则：钱包、浏览器、矿池、文档、网站。它们必须与规则共存，而不能改写规则。

此处的主张仍是架构主张。协议固定的是 **表面可以展示结论，不能充当结论**。它不把第八章的绿灯写成「整条链已被证明」。它也不把产品完整度写成共识完整度。

```
规则在节点里被承认或拒绝
        ↓
表面展示已公开的事实
        ≠
表面成为有效性来源
        ≠
形式化页面成为等价证明
```

第七章已经写过：矿池、浏览器、钱包、网站都可以展示一个结论，都不能充当那个结论。本章不是把那张表再抄一遍。本章堵住第八章之后最容易塌的那一步——把「已验证」印在产品表面上，当作正在运行的二进制的许可。

---

## 9.1 为何必须写共存

产品存在，是因为人需要看见余额、份额、高度和说明。看不见，规则就只存在于节点操作者之间，第一章要求的交换与参与无法发生。看见是参与的条件。

看见不是判定。第七章已经拒绝把有效性外包给一块屏幕。若不允许产品存在，协议无法被使用。若允许产品同时成为权威，第一章拒绝的对手方就从矿池看板换成了官网文案。共存的意思是：表面必须够用，权威必须仍在节点里。

形式化文档尤其危险。它说的是真的：模型里有被机器检查的不变式。真的句子被放在产品表面上之后，读者会自动补上没有写出来的那半句——「所以链已经被证明」。第八章不签发那半句。第九章禁止产品表面代为签发。

缩短允许的句子，就是改写诚实旗标。产品文案没有这份许可。

---

## 9.2 每个表面可以做什么，不可以做什么

| 表面 | 它可以 | 它不可以 |
|------|--------|----------|
| 全节点 `rigord` | 应用共识规则，承认或拒绝块 | 被网站、钱包或探索器的意见覆盖 |
| 钱包 | 构造、花费、显示余额与成熟 | 充当有效性预言机；把「已铸造」写成谓词已过 |
| 矿池 / 挖矿页 | 显示份额、高度、ORU 报酬 | 分配 RES；把欠付显示成合法入账 |
| 探索器 | 检索块、交易、指纹 | 接受或拒绝块；让 `VALID` 旗代替重算 |
| Zero Trust | 在浏览器里重算选定字段 | 替代 `ConnectBlock` 或全节点 |
| 白皮书 / 文档 | 绑定公开论证；指向活着的对照页 | 改写 `core/src/`；把某一天的向量计数写成参数 |
| 形式化验证页 | 公布证明了什么、没有证明什么 | 把 `equivalence_claimed` 写成 true |
| 实验室 / 实验 | 观察与研究 | 充当精化证明或「主网已完成」 |
| 官网 | 入口与说明 | 共识权威；「无缺陷」或「零风险」营销 |

使用路径（例如可见的挖矿步骤）见 [`07-mining-windows.md`](./07-mining-windows.md)。那是怎么点按钮，不是另一套共识规则。

钱包可以显示「已铸造 RES」。承认那笔 RES，仍然要看同笔销毁与谓词。矿池可以显示「已找到块」。承认那块，仍然要看 OpuHash、Merkle 与 coinbase。探索器可以显示指纹。核对指纹，仍然要从同一串字节算一遍。形式化页面可以显示绿灯。承认节点正在验证的块，仍然要在节点里重算——绿灯不是跳过第七章的许可。

## 9.3 第八章在产品表面上最容易被误读的三种方式

产品表面会把复杂边界压成徽章、标题和一句营销。下列三种压法都把第八章读成了它明确拒绝的那句：

```
「模型里的选定不变式已被证明」
        被压成
「整条链已被证明」
```

1. **省略「模型」二字。** 把 Coq 绿灯徽章放在首页或下载页，读者读到的是二进制，不是内核模型。
2. **把有限向量写成全称等价。** 差分闸锁住的案例一致，不能印成「C++ 已证明等于 Coq」。
3. **把「不必相信矿池」写成「不必运行节点」。** 第七章的对象是展示者，不是验证本身。判定仍须在某处执行。官网不是那一处。

产品文案只能重复第八章那一句对外宣传句，不得缩短，不得改写成「整条链已被证明」。缩短就是把诚实旗标改写成 true。本章不签发那一改写。

活着的入口仍是工具，不是多出来的共识层：`/zero-trust-verification` 把展示送回重算；`/documentation/formal-verification` 公布边界；钱包、挖矿、探索器供参与与观察。

---

## 9.4 文档工作不是共识变更

补全挖矿说明、校验和、占位页、章节 HTML，都是产品与文档工作。它们不改变谓词，不改变每块 128 ORU，不改变分类器，不改变导出上界。

若产品页上出现「下一步」，它只能是「这些表面如何写清楚」，不能是「这些规则将在某日改写」。规则已经冻结在运行中的节点里。表面跟在规则后面，不走在规则前面。

不为填满导出上界给出日期。不承诺投资收益。需求是否到来，仍不是规则——第二章已经写过。

---

## 9.5 本章不主张什么

- 不主张产品表面已经完备，也不把占位页写成协议缺口。
- 不主张浏览器重算可以替代全节点。
- 不主张官网或白皮书是事实源。事实源是 `core/src/`。
- 不把形式化页面写成等价已成立，也不把实验页写成精化证明。
- 不把「可见的挖矿」写成有效性来源。
- 不把本章的表面清单写成另一套共识规则。

**展示仍是展示。规则仍在节点里。** 附录给出冻结参数与工程索引——那是查阅，不是另一套主张：[`10-appendix.zh.md`](./10-appendix.zh.md)。
