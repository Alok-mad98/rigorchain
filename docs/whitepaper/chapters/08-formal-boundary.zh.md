# 第八章 — 形式化的边界：模型不是正在运行的二进制

第七章要求本地重算。重算的是节点正在验证的字节，执行它的是 C++ 节点。本章给出当前最终形式化结论：对外只能宣传一句；「是」停在模型内部。

此处的主张仍是架构主张。协议公布 **证明了什么** 与 **没有证明什么**。它不把绿灯构建说成「整条链已被形式化证明」。

```
形式化验证的是协议模型里的性质
        ≠
C++ 实现等价
        ≠
正在运行的二进制证明
        ≠
完整系统验证
```

最终结论只写在 8.5。前面各节说明边界与规模，不另给宣传句。

---

## 8.1 为何必须划界

关于数学模型的定理，不会自动变成关于每一行节点代码、每一条网络路径、每一个钱包的定理。若把三层叠成一句「已完全验证」，绿灯 Coq 与绿灯差分闸就会被读成 `equivalence_claimed = true`。那一许可本章不签发。

划界是为了让前面各章的规则保持可核对，而不把核对偷换成权威：

| 层 | 它是什么 | 它不是什么 |
|----|----------|------------|
| 运行共识 | C++ 节点 `core/src/`。代码是唯一事实源 | RFC、SPEC、Coq 不能改写正在跑的规则 |
| Coq 内核模型 | 机器检查的、关于模型的性质 | C++ 精化证明；`ConnectBlock` |
| 差分 / 抽取 | 有限黄金向量、源代码身份、声明的运行时路径 | 全称等价；验证编译器已进入当前信任基 |

---

## 8.2 模型里已经有的成果（快照，不是参数）

内核在 `formal_verification/rigor_kernel/`。下列数字让人看见规模。它们是一份 **快照**，不是协议参数，也不是「定理越多就越等于 C++」。活清单由构建再生：`release/FinalProofInventory.md`。突变闸：`release/MutationCompletenessAudit.md`。公开说明：`/documentation/formal-verification`。

| 项 | 快照 | 它不是 |
|----|------|--------|
| 证明器 | Coq 8.15.0 | 验证编译器；Level 5 |
| 已分类定理 | 254 | C++ 里的定理数 |
| Category A | 119（可被公开引用的核心不变式） | 「整条链的定理」 |
| Category B | 102（支撑引理） | 不得单独写成领域可靠性 |
| Category C | 33（边界 / 非主张） | 不变式证据 |
| `Print Assumptions` | 全部 Closed under the global context | 无公理洞等于二进制正确 |
| 成熟度 | 4.9 | Level 5；`rigord` 已被证明 |
| 突变闸 | 隔离击杀；当前清单 127 | 运行中的节点等于被击杀的那条定理 |
| 抽取 | 六个抽取名与 Coq 判定器定义等同 | 抽出的 OCaml 计算的就是 Coq 函数 |
| 编解码差分 | 字节对照生产 `CDataStream`；已声明 3 处分歧 | 精化证明 |

分类的意思是：A 才进入公开主张；B 支撑 A，不能单独拿来当「该领域已证明」；C 是边界与非主张，包括诚实旗标本身。把 254 读成「整条链有 254 条已被证明的运行规则」，就是把三层又叠回去。

数字会变。写入本章是为了让边界可核对，不是把某一天的计数冻进共识。

---

## 8.3 对照不是精化

8.5 里能答「是」的那些名字，与本白皮书的规则同名，可以对照阅读。对照不是精化证明。它们不让任何人跳过第七章的重算。即使模型里得到「是」，节点正在验证的字节仍须与承诺比较。

哈希在模型里是未解释符号 `H`。关于 SHA3 或 Ed25519 **安全** 的定理不存在。抽象 `sig_ok` 不是不可伪造。

---

## 8.4 明确落在边界之外的

下列事项 **没有** 被证明。不是暂时没写进附录，是本章的边界：

- C++ ↔ Coq ↔ Python 全称等价
- `ConnectBlock` 是模型迁移的精化
- 抽取后的代码计算的就是 Coq 函数
- 编译器正确（`ocamlopt` 被信任）
- k 深确认 / 诚实多数（工作量竞赛，不是发行恒等式）
- ASERT 相对 `2ˣ` 的包络
- 密码原语的安全性（超出可执行哈希模型与向量检查）
- 硬件、侧信道、P2P 诚实、内存池、钱包假设

差分闸用有限黄金向量连接规格与实现：锁住的案例回归时，构建或闸失败。有限案例失败能抓住回归。它不能把「这些点上一致」写成「所有点上等价」。

测试不是证明。突变分析可以表明某个定理在模型被改坏时会碎。它不能表明运行中的节点等于该定理。

---

## 8.5 最终形式化结论

对外只能宣传这一句：

> 在 Coq 共识内核模型里，关键共识不变式已被机器检查证明，并带有明确的抽取与运行时信任边界。

项目能得到「是」的，是：这套 Coq 模型内部的选定不变式成立——例如内核健全性、ORU 守恒、RES 上限、分类器划分、链上归纳。公开分类下 `Print Assumptions` 为 Closed。

得不到「是」的，是：正在运行的 C++ 节点等于该模型。

不得把上一句塌成「整条链已被证明」「无缺陷」「不必再重算」。诚实旗标保持为假，直到有一份精化证明把它们改写。

---

## 8.6 本章不主张什么

- 不主张 Level 5，不主张验证编译器已在当前信任基里。
- 不把某一天的定理计数或突变计数写成协议参数。
- 不把研究档案或实验页写成等价证明。
- 不把「模型强验证」写成「主网已完成」。

活着的对照与复现：`docs/verification/FORMAL-VERIFICATION-VERDICT.md`（模型证明了什么），`docs/security/HOW_TO_VERIFY_RIGOR.md`（如何复现）。工程前沿：`formal_verification/rigor_kernel/release/FormalizationFrontier.md`。分类清单：`formal_verification/rigor_kernel/release/FinalProofInventory.md`。

**证明的是模型。运行的是 C++。二者尚未被证明为同一件东西。** 第九章说明产品表面如何与这套规则共存——展示仍是展示，不能把第八章说成「整条链已被证明」。
