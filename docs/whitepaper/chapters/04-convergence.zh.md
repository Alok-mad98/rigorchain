# 第四章 — Convergence：单向桥如何被验证

第三章给出两枚原生身份。若没有一座公开、确定的桥，它们只是两枚互不相干的账本对象：矿工预算与稀缺存量再次脱节。本章说明这座桥如何被每一个全节点验证。

此处的主张仍是架构主张。协议固定的是 **一次可见的销毁，以及同一笔交易里的整数谓词**。它不固定有人会销毁，也不固定二级比价。

```
ORU 输入
        ↓
恰好一个 OP_CONVERGE 输出，面额 B（销毁，不进 UTXO）
        ↓
同一笔主体交易里，Witness v1 RES 输出合计 R
        ↓
确认高度 h 上：R > 0 → R · (2²⁵ + h)² ≤ B << 40
```

没有 Convergence，就没有新的 RES。

---

## 4.1 桥是单向的、原子的、可重放的

第一章把三个顶点分给两枚资产。第二章把变换写成规则。第三章把身份写成分类。还缺一步：变换必须发生在 **同一串交易字节** 里，并且任何诚实节点重放这串字节，得到同一判定。

若销毁在一笔交易、铸造在另一笔，账本就会出现「先记一笔 RES、销毁稍后补上」的窗口。那是信用，不是销毁。若销毁从 `输入 − 输出 − 手续费` 反推，它可能与普通手续费记账无法区分，验证者无法指出「哪一枚输出是被烧掉的」。若铸造由矿工在 coinbase 里赏给谁，桥就变成矿工裁量。

因此 Convergence 有三条不可拆开的要求：

1. **销毁可见** — 一枚显式的、不可花费的 `OP_CONVERGE` 输出，面额就是 `B`。
2. **铸造同笔** — 若有 RES 输出，必须与这枚销毁在同一笔主体交易里。
3. **谓词整数** — 承认或拒绝只看 `R`、`B`、`h`。同一组数，同一结果。

方向只有一条：ORU 可以消失并（在谓词成立时）使 RES 出现。RES 不能兑回 ORU。

---

## 4.2 它是什么

**Convergence** 是共识动作：把 ORU 销毁进 `OP_CONVERGE`（`RIGOR_MARKER_CONVERGE`，`<20 字节 HASH160> 0xbd`）。被销毁的 ORU 离开流通。同一笔交易 **可以** 铸造 Witness v1 RES，成本由确认高度上的协议谓词裁定。

它不是：

- 挖矿。工作量证明只排序历史、支付 ORU。
- 1:1 柜台。销毁的 ORU 不会改名为等额 RES。
- 抽签。没有人被「抽中」，也没有窗口里的中奖哈希。
- 智能合约。没有字节码可部署，没有状态机可步进。
- 矿工奖赏。RES 的接收者是该笔交易的 RES 输出，不是 coinbase。

钱包可以构造这枚销毁输出。钱包不能花费它。节点验证后不把它插入 UTXO 集。

`R = 0` 是合法的纯销毁：ORU 被移除，不铸造 RES。销毁本身是完整动作。铸造是可选的、有代价的后续。

---

## 4.3 销毁必须可见

销毁由一枚显式输出声明，而不是从余额差推断。

```
scriptPubKey = PUSHBYTES_20 || HASH160(...) || 0xbd
nValue       = B  ≥ 1 原子
```

`B` 是铸造算术里的销毁量。最低 1 原子是「这是一枚销毁输出」的门槛，不是铸造价格。创世高度铸造 1 枚 RES 原子所需的最小 `B` 是 1 024 枚 ORU 原子；铸造 1 整枚 RES 所需的最小 `B` 是 `destroy_cost(h)` 对应的原子数。

约束：

| 规则 | 为何如此 |
|------|----------|
| 每笔交易至多一个正值 Convergence 输出 | `B` 必须是单点声明，不能拆成多处让验证歧义 |
| 只能花费 ORU 输入 | RES 不能充当销毁原料，否则方向反了 |
| 输出不进入 UTXO 集 | 被烧掉的东西不能再被花费 |
| 分类为 ORU 域 | 它是流量的汇，不是一枚 RES |

若没有这枚输出却出现了 RES 输出，交易无效：`bad-txns-res-mint-no-burn`。没有可见销毁，就不承认铸造。

---

## 4.4 铸造必须在同一笔交易

铸造住在 **区块体** 里，不住在 coinbase。一笔 Convergence 交易的形状是：

```
输入          仅 ORU
输出          恰好一个 OP_CONVERGE，面额 B
              零个或多个 Witness v1 RES，合计 R
              可选的 ORU 找零
手续费        oru_in − B − oru_找零，仍用 ORU 支付
```

`R` 是该笔交易所有新 RES 输出之和。谓词对这个和一次裁定。矿工打包这笔交易，并不因此获得 RES。矿工仍然只领取 coinbase 里的 ORU。

同一笔，是为了原子性。验证者看见的要么是「`B` 已销毁，且 `R` 被谓词承认」，要么是整笔无效。不存在「RES 已出现、ORU 尚未销毁」的中间账本状态。

普通 RES 转账不能创造 RES：`res_in ≥ res_out`。销毁 RES（`res_in > res_out`）只会收紧存量，不会兑回 ORU。

---

## 4.5 整数谓词，不是牌价

共识从不计算展示式。整数谓词是铸造条件的精确整数形式，与展示成本条件代数等价。不发生舍入或截断。共识计算消去除法后的那一关系：

```
R > 0  →  R · (2²⁵ + h)² ≤ B << 40
R = 0  →  B 不受此谓词约束
```

`h` 是 **确认高度**，不是构造时的钱包估计。展示式仅供阅读：

```
destroy_cost(h) = 1024 · (2²⁵ + h)² / 2⁵⁰
destroy_cost(0) = 1024 ORU / 整枚 RES
```

`2⁵⁰` 是曲线归一化分母，不是共识移位。`B << 40` 中的 `2⁴⁰` 是整数共识缩放因子，不是 `destroy_cost` 的分母。展示辅助函数按 `/ 2⁵⁰` 做的 rounding/floor 不进入共识。

同一高度、同一 `B`、同一 `R`，每一诚实节点承认或拒绝的结果相同。没有矿工裁量，没有未公开的费率，没有除法、开方、epoch 指数进入谓词。

`destroy_cost(h)` 是协议销毁要求，不是市场报价。铸造开放期间，二级比价若高于该要求，会被铸造套利拉回；低于该要求，铸造停止。协议不发布牌价。

`R` 可以是任意正的 RES 原子数。可以铸造不足一整枚。「一枚 RES 值多少 ORU」是 `R = RES_COIN` 时的标题读法，不是构造时必须烧掉的整数——构造必须满足不等式本身。

没有每块铸造上限。一块可以吸收任意大的销毁。限速的缺席是故意的：需求应当能在单块内被全部吸收，而不是排进一条协议队列。

---

## 4.6 为何不是 1:1 柜台

1:1 会削弱两枚身份之间的预定分离：毁掉多少流量，就出现多少存量。那是改名，不是变换。第一章的三角形将不再把三个顶点分给两枚不同的资产。

协议付出的代价随高度上升。更早的铸造者为更长的剩余保护期支付更低的单位成本。被销毁的 ORU 离开 `S_ORU`。新的 RES 进入 `S_RES`，是一枚新的 Witness v1 UTXO。没有字段把旧输出「涂成」RES。

反向路径不存在。试图把 RES 当 ORU 花，或把 Convergence 输出再花出去，都是无效交易。

---

## 4.7 为何不是抽签

抽签把「谁获得 RES」交给哈希或操作者。验证者必须相信随机源，或相信窗口里的中奖规则。同一组公开输入，可以因一次哈希而得到不同分配。

Convergence 的裁定不含随机项。给定 `R`、`B`、`h`，结果是承认或拒绝。没有人被选中。没有人被跳过。费用高的人不能买到更高的中签率，因为根本没有签。

矿工不能在 coinbase 里写入 RES。矿工不能把 RES 指派给自己的地址来「奖励」出块。池策略不能分配 RES。改矿工收款地址不能创造 RES。

共识规则内的公平，定义为对同一公开不等式的确定性求值。数学展开是第五章的主题。本章只固定验证动作本身。

---

## 4.8 验证失败时发生什么

活着的拒绝码说明验证在哪一条上失败：

| 拒绝 | 含义 |
|------|------|
| `bad-txns-res-mint-underpaid` | `R · (2²⁵ + h)² > B << 40`：销毁不够支付所请的铸造 |
| `bad-txns-res-mint-no-burn` | 有 RES 输出，没有 `OP_CONVERGE` |
| `bad-txns-res-mint-cap-overshoot` | 运行时防御；第二章的导出上界表明它不可达 |
| `illegal-res-to-oru-conversion` | 方向反了，或试图花费 Convergence 输出 |

欠付则整笔无效。没有「先记上、以后再补销毁」的部分成交。

铸造成熟 100 块。这与 coinbase 成熟同一深度：重组保护。它不是等待开奖。内核模型证明选定的重组回滚恒等：断开孤块再接另一后缀，等于从未应用那些孤块。那不是 `ConnectBlock` 的等价证明。

---

## 4.9 本章不主张什么

- 不主张有人会销毁 ORU，或 `ρ` 会落在某一区间。
- 不把 `destroy_cost(h)` 写成市场价格。
- 不把成熟 100 写成抽签等待。
- 不主张 C++ 与内核模型形式等价。
- 不把 Convergence 写成合约、柜台或矿工奖。

**销毁是可见的。铸造是同一笔交易里的整数谓词。** 第五章把这条谓词展开为可核对的数学：导出上界、强制的共识缩放因子、以及「同一输入同一判定」何以成为公平。

本章给出概念机制。代数推导、整数谓词变换、上限推导与公平解释见附录 D：
[`RIGOR_CONVERGENCE_MATHEMATICAL_NOTE.zh.md`](../RIGOR_CONVERGENCE_MATHEMATICAL_NOTE.zh.md)。
该数学设计说明是解释性文档。它不引入新的共识规则。

Convergence 曲线定义的是确定性的协议发行成本。
它不定义市场价格、盈利能力或未来需求。
不同高度之间的发行成本差异，不构成任何经济收益保证。
