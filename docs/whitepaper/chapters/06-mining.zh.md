# 第六章 — 工作量证明：共用的高度，支付的是 ORU

第五章的谓词含有确认高度 `h`。展示式、移位、导出上界，全都是 `h` 的函数。若节点对「哪一块收入了这笔交易」意见不一，同一笔销毁就会在不同高度上被求值。本章说明工作量证明如何给出共用的高度，以及出块者领取什么。

此处的主张仍是架构主张。工作量证明固定的是 **顺序与报酬资产**。它不固定谁会出块，也不固定算力的外部价格。

```
算力寻找有效块头
        ↓
全网承认同一条主链顺序
        ↓
确认高度 h 对所有诚实节点相同
        ↓
谓词在这个 h 上裁定 Convergence
coinbase 在这个 h 上支付 128 ORU
```

挖矿 **支付 ORU**。挖矿 **不铸造 RES**。

```
PoW
 |
 v
ORU 安全预算

Convergence
 |
 v
RES 发行
```

挖矿安全与储备发行是有意分开的机制。工作量证明不决定 RES 供给。

---

## 6.1 谓词需要一个共用的高度

`destroy_cost(h)` 严格递增。第一章的按时长付费、第五章的导出上界，都依赖「更晚的高度更贵」。高度若可以由本地时钟、钱包估计或矿工填写的任意整数充当，同一串交易字节就可以在不同节点上对着不同的 `h` 计算。

工作量证明给出的不是墙钟时间。它给出一条链上顺序。重写该顺序需要重复相应的工作量。协议不主张：在足够算力下历史不可被改写。它主张：诚实节点重放同一条被承认的链，得到同一个高度索引。

后一块承认前一块，高度加一。Convergence 的确认高度是这笔交易被收入的那一块的高度，不是构造时的猜测。

没有这个共用索引，第五章的公平——同一 `(R, B, h)` 同一判定——就缺少第三个分量的公共来源。

---

## 6.2 挖矿做什么，不做什么

工作量证明做两件事：发现有效块头，并把历史排成一条链。它不创造 RES，不选择谁获得 RES，不改写 `destroy_cost`。

| | 挖矿给出 | 挖矿不给出 |
|--|----------|------------|
| 顺序 | 被承认的高度 `h` | 市场报价 |
| 报酬 | Coinbase 里的 128 ORU（`h ≥ 1`） | RES |
| 对桥的作用 | 让所有人在同一 `h` 上算谓词 | 在 coinbase 里铸造或指派 RES |

创世块补贴为 0。此后每一块 `128` ORU，付给该块 coinbase 指定的 Witness v0 脚本。这是第一章的矿工预算顶点：流量资产上有协议地板，不依赖于 SoV 持有者是否交易。

把 RES 放进挖矿报酬，等于用增发存量来买安全，并把两种货币职能重新叠回同一代码。因此 RES 若出现，只出现在区块体里的 Convergence 交易中，且必须满足第四章的可见销毁与整数谓词。

---

## 6.3 有效头如何被承认

现行工作量证明摘要是 **OpuHash**。它是带域标签的 SHA3-256：

```
OpuHash(header) = SHA3-256("RGRPOW01" || header_80)
有效             ⇔  OpuHash(header) ≤ target
```

OpuHash 用于 **PoW 有效性**。区块 **身份** 仍是同一 80 字节头的 SHA256d。Merkle 与 txid 仍是 SHA256d。二者不可互换：核对工作量用 OpuHash；指称一个块用 SHA256d。

节点组装块模板（GBT）。SOLO 矿工复制节点给出的 coinbase 字节，只把可变字段留在时间戳，然后研磨 nonce，再 `submitblock`。Coinbase 只写明本块高度，只付 ORU。

矿工打包进块的 Convergence 交易若有效，是因为销毁可见、谓词成立，不是因为出块者选择了它作为奖赏。出块者仍然只领取 coinbase 的 ORU。

## 6.4 难度如何让高度继续前进

目标出块间隔 600 秒。难度按 ASERT（aserti3-2d）调整，主网半衰期 43 200 秒，每块夹紧 ±12.5%。求值只用父块的时间与高度，不含本块 `nTime`。锚在高度 1 一旦存在；生产高度 1 时用创世。

ASERT 不改发行规则。它按父块时间戳调节难度，使出块间隔趋向 600 秒目标。高度本身仍是块计数索引。ASERT 不把 `h` 绑定到墙钟时间，也不进入铸造谓词。难度不是铸造价格。`destroy_cost(h)` 仍只随高度变化——单块约 0.000 089%。

内核模型在有限链尖上按 `GetBlockProof` 做最多工作量选择。它不证明 `ActivateBestChain`，也不证明 ASERT 相对 `2ˣ` 的包络。那不是本章的存在理由。

## 6.5 两笔出生地不混用

| | ORU 补贴 | RES 铸造 |
|--|----------|----------|
| 位置 | Coinbase | 区块体，同一笔 Convergence |
| 谁收到 | 矿工脚本 | 该笔交易的 RES 输出 |
| 每块 | 128 ORU（`h ≥ 1`） | 谓词允许的任意 `R`，可以为 0 |
| 谁能决定数量 | 协议函数 `subsidy(h)` | 销毁者选择 `B` 与请求的 `R`，再由谓词裁定 |

矿池策略不能分配 RES。改矿工收款地址不能创造 RES。GBT 的 coinbase 地址必须是 ORU Witness v0。把 RES 写进 coinbase，块无效。

没有 Convergence，就没有新的 RES。有 Convergence 而谓词失败，整笔无效。已经算出一个有效头，并不能把欠付铸造变成合法铸造。

## 6.6 这如何接回第一章

单资产系统里，出块报酬与稀缺存量是同一枚单位：要么增发稀释储备叙事，要么停发把安全交给手续费。RIGOR 把报酬放在 ORU 上，创世后每块 128，使安全预算不依赖 SoV 用户是否交易；把存量放在 RES 上，使挖矿不会增发储备。

矿工出售的是排序与安全——对整条历史的持续保护，包括已经存在的 RES。他们用 ORU 收取这笔流量报酬。想进入存量的人，走第四章的桥，按第五章的曲线销毁 ORU。两类用户在同一高度上相遇，但不从同一笔 coinbase 里取款。

可见的挖矿路径可以让人看见：份额、高度、ORU 成熟、以及（若发生）钱包里的 Convergence。产品流程见 [`07-mining-windows.md`](./07-mining-windows.md)。那是使用路径，不是另一套共识规则。

---

## 6.7 本章不主张什么

- 不主张诚实多数，也不主张某一种算力分布。
- 不主张工作量证明使历史不可改写。
- 不主张 C++ 与内核模型形式等价，不证明 `ActivateBestChain`。
- 不把 OpuHash 写成区块身份哈希。身份仍是 SHA256d。
- 不把难度或墙钟时间写成铸造价格。
- 不把矿池看板或网站写成有效性来源。有效性是承诺与重算相等，见第七章。

**高度是共用的。报酬是 ORU。RES 不从挖矿里出现。** 第七章说明公开数据如何通过本地重算被独立验证。
