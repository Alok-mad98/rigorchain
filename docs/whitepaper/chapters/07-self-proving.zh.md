# 第七章 — 本地验证：对公开数据的独立校验

第六章给出共用的高度，并写明所展示的挖矿状态不是有效性来源。本章说明替代物是什么：公开字节在本地重算，相等则承认，不等则拒绝。

此处的主张仍是架构主张。协议固定的是 **承诺与重算必须相等**。它不主张欺骗不可能发生。它主张不相等的字节通不过已公布的检查。

```
公开数据
        ↓
独立计算
        ↓
与承诺比较
        ↓
承认 / 拒绝
```

探索器、矿池、钱包和网站都可以 **展示** 数据。共识有效性由全节点对同一串公开字节求值来决定。

角色保持分离：

| 主体 | 角色 |
|------|------|
| 探索器 | 展示（displays） |
| 节点 | 判定（decides） |
| 钱包 | 构造（constructs） |
| 验证者 | 重算（recomputes） |

展示结果是观察。共识有效性由独立验证决定。

---

## 7.1 展示不是共识判定

挖矿软件、探索器、钱包存在，是为了让人查看份额、余额、高度。查看不是承认。

若把所展示的结论当作共识，展示本身就成了对手方。第一章关于安全与去中心化的设定，要求有效性仍是对公开数据的本地求值，而不是外包给一块屏幕。

预期习惯不是「换一个更有权威的网站」，而是：

```
先拿到公开字节，再跑同一函数，再比较
```

全节点 `rigord` 对接收到的块做这件事。浏览器里的 Zero Trust 页面对选定字段做这件事。任何人用纸笔对 `(R, B, h)` 做第五章的不等式，也是在做这件事。规模不同，标准相同：相等则过，不等则不过。

---

## 7.2 哪些字节是公开的

Convergence 与出块没有「内部交易」通道。裁定所需的输入都在已广播的数据里：

| 对象 | 公开在何处 | 本地重算什么 |
|------|------------|--------------|
| 销毁 `B` | `OP_CONVERGE` 输出的面额 | 是否存在、是否唯一、是否来自 ORU |
| 铸造 `R` | 同笔 Witness v1 输出之和 | 是否满足 `R · (2²⁵ + h)² ≤ B << 40` |
| 高度 `h` | 该交易所在块的高度 | 是否与链上顺序一致 |
| Coinbase | 块内第一笔交易 | 是否只写明本块高度、是否只付 ORU |
| Merkle 根 | 块头 | 是否等于交易列表的重算根 |
| 工作量 | 80 字节头 | `OpuHash(header) ≤ target` |
| 区块身份 | 同一 80 字节头 | SHA256d，与 OpuHash 不是同一个哈希 |

改其中任何一步而不改后续承诺，重算就会不相等，块无效。有效性是承诺与重算相等，不是探索器上的一面旗。

---

## 7.3 一条可以走完的承诺链

一个可被第三方再生的块，沿着同一条绑定往下走：

```
主体交易
        ↓
OP_CONVERGE 销毁 B
        ↓
Witness v1 RES 输出合计 R（可以为 0）
        ↓
R > 0 → R · (2²⁵ + h)² ≤ B << 40
        ↓
coinbase（只写明本块高度，只付 ORU）
        ↓
coinbase txid
        ↓
merkle root
        ↓
块头
        ↓
OpuHash = SHA3-256("RGRPOW01" || header_80)
```

任一步对不上，块无效。探索器可以显示 VALID；块仍然只有在重算一致时才有效。Coinbase 只写明本块高度，只付 ORU。欠付的铸造在谓词上失败。矿池入账展示并不能使它有效。

这就是自证：块不是因为被展示而有效，而是因为被重算而有效。

---

## 7.4 各表面的职责

| 表面 | 它是什么 | 它不是什么 |
|------|----------|------------|
| 全节点 `rigord` | 应用共识规则，承认或拒绝块 | 网站的后端意见 |
| 钱包 | 构造与花费；可以展示余额 | 共识有效性来源 |
| 探索器 / 索引器 | 查看与检索公开数据 | 共识 |
| 矿池看板 | 运营者观察份额与算力 | 出块合法性来源 |
| 网站 Zero Trust | 在浏览器里重算选定字段 | 对全节点的替代 |

钱包可以显示「已铸造 RES」。那是花费工具的界面。承认那笔 RES，仍然要看同笔销毁与谓词。矿池可以显示「已找到块」。承认那块，仍然要看 OpuHash、Merkle 与 coinbase。探索器可以显示指纹。核对指纹，仍然要在本地从同一串字节算一遍。

---

## 7.5 指纹是观察层，不是规则

**共识指纹** 对已经公开的字段发布一个确定的身份。它是观察性的。它不接受块，也不拒绝块。

不匹配的指纹不能让无效块变有效。匹配的指纹不能代替全节点验证。探索器可以展示它。验证者重算它。相等只表示「发布的身份与本地字节一致」，不表示发布者是权威。

Zero Trust 页面与探索器上的独立验证出口，存在的理由就是把展示送回重算。活着的入口是 `/zero-trust-verification`。它们是工具，不是多出来的共识层。

---

## 7.6 本章不主张什么

- 不主张欺骗不可能。主张不相等的字节会失败。
- 不主张浏览器重算可以替代全节点。选定字段的重算不是 `ConnectBlock`。
- 不主张指纹是共识规则。
- 不主张 C++ 与内核模型形式等价。模型证明是第八章的主题；即使模型成立，节点正在验证的字节仍须重算。
- 不把独立验证写成「不必运行验证器」。判定必须在某处执行：节点、本地程序、或纸笔。只是执行者不需要是展示者。

**结论可以展示。有效性必须重算。** 第八章划清形式化证明的边界：模型里成立的不变式，不等于正在运行的二进制已被证明等价。
