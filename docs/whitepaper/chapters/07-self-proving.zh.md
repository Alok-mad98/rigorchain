# 第七章 — 本地重算：不必相信矿池或浏览器

第六章给出共用的高度，并写明矿池看板不是有效性来源。本章说明替代物是什么：公开字节在本地重算，相等则承认，不等则拒绝。

此处的主张仍是架构主张。协议固定的是 **承诺与重算必须相等**。它不主张欺骗不可能发生。它主张不相等的字节通不过已公布的检查。

```
公开数据
        ↓
独立计算
        ↓
与承诺比较
        ↓
承认 / 拒绝
```

矿池、浏览器、钱包、网站都可以 **展示** 一个结论。它们都不能 **充当** 那个结论。

---

## 7.1 为何展示不是判定

挖矿、浏览器、钱包存在，是因为人需要看见份额、余额、高度。看见与判定不是同一件事。

若有效性来自矿池看板，出块者与记账者就合成了对手方。若有效性来自浏览器的「VALID」标记，索引器就成了共识。若有效性来自钱包界面，花费工具就成了预言机。第一章要求安全与去中心化；把判定外包给一块屏幕，等于重新引入对手方风险。

替代习惯不是「换一个更可信的网站」，而是：

```
不要先相信软件，再接受结果
先拿到公开字节，再跑同一函数，再比较
```

全节点 `rigord` 对接收到的块做这件事。浏览器里的 Zero Trust 页面对选定字段做这件事。任何人用纸笔或一段程序对 `(R, B, h)` 做第五章的不等式，也是在做这件事。规模不同，标准相同：相等则过，不等则不过。

---

## 7.2 哪些字节是公开的

Convergence 与出块没有「内部交易」通道。裁定所需的输入都在已广播的数据里：

| 对象 | 公开在何处 | 本地重算什么 |
|------|------------|--------------|
| 销毁 `B` | `OP_CONVERGE` 输出的面额 | 是否存在、是否唯一、是否来自 ORU |
| 铸造 `R` | 同笔 Witness v1 输出之和 | 是否满足 `R · (2²⁵ + h)² ≤ B << 40` |
| 高度 `h` | 该交易所在块的高度 | 是否与链上顺序一致 |
| Coinbase | 块内第一笔交易 | 是否只写明本块高度、是否只付 ORU |
| Merkle 根 | 块头 | 是否等于交易列表的重算根 |
| 工作量 | 80 字节头 | `OpuHash(header) ≤ target` |
| 区块身份 | 同一 80 字节头 | SHA256d，与 OpuHash 不是同一个哈希 |

改其中任何一步而不改后续承诺，重算就会不相等，块无效。有效性是承诺与重算相等，不是探索器上的一面旗。

---

## 7.3 一条可以走完的承诺链

一个可被第三方再生的块，沿着同一条绑定往下走：

```
主体交易
        ↓
OP_CONVERGE 销毁 B
        ↓
Witness v1 RES 输出合计 R（可以为 0）
        ↓
R > 0 → R · (2²⁵ + h)² ≤ B << 40
        ↓
coinbase（只写明本块高度，只付 ORU）
        ↓
coinbase txid
        ↓
merkle root
        ↓
块头
        ↓
OpuHash = SHA3-256("RGRPOW01" || header_80)
```

任一步对不上，块无效。没有人需要相信探索器写了 VALID。Coinbase 只写明本块高度，只付 ORU。欠付的铸造在谓词上失败，不能靠「矿池已经显示入账」变成有效。

这就是自证：块不是因为被展示而有效，而是因为被重算而有效。

---

## 7.4 各表面的职责

| 表面 | 它是什么 | 它不是什么 |
|------|----------|------------|
| 全节点 `rigord` | 应用共识规则，承认或拒绝块 | 网站的后端意见 |
| 钱包 | 构造与花费 | 有效性预言机 |
| 浏览器 / 索引器 | 查看与检索 | 共识 |
| 矿池看板 | 运营者观察份额与算力 | 出块合法性来源 |
| 网站 Zero Trust | 在浏览器里重算选定字段 | 对全节点的替代 |

钱包可以显示「已铸造 RES」。那是花费工具的界面。承认那笔 RES，仍然要看同笔销毁与谓词。矿池可以显示「已找到块」。承认那块，仍然要看 OpuHash、Merkle 与 coinbase。探索器可以显示指纹。核对指纹，仍然要在本地从同一串字节算一遍。

---

## 7.5 指纹是观察层，不是规则

**共识指纹** 对已经公开的字段发布一个确定的身份。它是观察性的。它不接受块，也不拒绝块。

错的指纹不能让无效块变有效。对的指纹不能代替全节点验证。探索器可以展示它。验证者重算它。相等只表示「发布的身份与本地字节一致」，不表示发布者是权威。

Zero Trust 页面与探索器上的「独立验证」出口，存在的理由就是把展示送回重算。活着的入口是 `/zero-trust-verification`。它们是工具，不是多出来的共识层。

---

## 7.6 本章不主张什么

- 不主张欺骗不可能。主张不相等的字节会失败。
- 不主张浏览器重算可以替代全节点。选定字段的重算不是 `ConnectBlock`。
- 不主张指纹是共识规则。
- 不主张 C++ 与内核模型形式等价。模型证明是第八章的主题；即使模型成立，节点正在验证的字节仍须重算。
- 不把「不必相信矿池」写成「不必运行验证」。判定必须在某处执行：节点、本地程序、或纸笔。只是执行者不需要是展示者。

**结论可以展示。有效性必须重算。** 第八章划清形式化证明的边界：模型里成立的不变式，不等于正在运行的二进制已被证明等价。
